## 关键实现

- 本机桥接仅监听回环地址、独立鉴权，Docker Desktop 实测可通过 host.docker.internal 访问。串行模型队列、输出限长、超时取消、24 小时持久结果缓存；失败及结果不明不自动重复调用。
- 编写尝试绑定任务与人工重试次数；重复回调不能启动新的调用。保留原确认流程、事实占位、正文检查和 Word 导出，Codex 路径使用纯文本技术方案。
- 预读兼容补丁接受数字页码字符串，原样保留多页范围并降低置信度；未知强制性、可补齐性、评分分类保持未知，不使用 false 或任意分类代替。
- 缓存回放入口复用原子报告落库，并捕获新的交接快照。同一正文的报告更正形成新报告版本，旧卡确认与旧稿投递被阻断。
- 卡片把预读内部字段转换为中文，识别有证据的中文截止日期；冲突、非法日期和未确认日期均保持待核实，更正后的截止时间优先于旧值。
- 雷达游标、来源编辑隔离、正文获取阶段、卡片更新和附件投递均有持久状态；执行结果不明时保留人工核对，不能重复上传已解决的补件动作。

## 验证与部署

消费者补丁在独立 checkout 构建，旧飞书平台未提交文件未修改。完整依赖安装曾使 Docker Desktop 中断；随后恢复 Docker，使用已有 Linux 镜像依赖加独立编译的 dist 构建派生镜像，原镜像保留。补丁、基线、哈希和复现脚本见 `integrations/feishu/deployment/preread-compat/`；future producer prompt patch 未部署，确保缓存请求保持一致。

消费者原 243 项聚焦测试通过；评分类别继承属性回归通过；后续报告捕获、控制器与真实数据库存储链路 83 项通过，Nest 构建通过。实际缓存回放和群内回读独立完成。OpenBid 最终完整回归 200/200 通过、无跳过，串行约 42 秒。内存压力下曾出现 Electron／监管器启动超时；监管器单测复核通过，真实 Electron 导出在较长启动窗口下通过，因此离线验收的单阶段超时从 15 秒调至 45 秒，生产 Worker 的 30 分钟上限未变。最终完整套件重新通过。

主运行目录由 `\OpenBidKitFeishu` 登录任务监管，使用现有 PowerShell 7 RemoteSigned 配置，未修改系统执行策略。主服务 `127.0.0.1:4381`、桥接 `127.0.0.1:4383` 实测 ready 200。仅在当前用户登录且电脑运行时持续接收；关机、注销、休眠期间不保证服务。
