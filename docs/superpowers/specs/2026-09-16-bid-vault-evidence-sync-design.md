# BidVault 公司证据同步设计

## 目标

把本机“业绩资质查询工具”BidVault 中的结构化业绩、人员证照和扫描件同步到易标商务标的公司证据库，使用户可以按招标资格要求搜索、匹配并选用已有材料。同步只读取 BidVault，不修改其 SQLite、附件或设置。

首期数据固定归属“隆创信息有限公司”。现有源库共 1,638 条记录，其中业绩 1,481 条、人员证照 157 条；共有 3,820 个附件，约 9.47 GB。源记录均存在“隆创”关联信息，未发现“贵州云界科创信息技术有限公司”标识，因此云界公司不接收本次数据。

## 用户流程

商务标“匹配并人工确认公司材料”区域增加“同步业绩资质库”按钮。按钮明确显示同步目标为当前公司；当前公司不是“隆创信息有限公司”时不执行同步，并提示切换主体。

同步完成后，页面显示来源、同步时间和统计结果。用户可以继续用现有关键词与“只看可选”筛选材料，勾选材料并关联具体资格要求。空关键词时最多渲染前 100 条并提示继续搜索，避免一次创建 1,600 多个详情节点拖慢页面。

原有“导入公司证据台账”JSON 入口继续保留，手工导入材料与 BidVault 同步材料可以共存。

## 数据读取与映射

新增只读 BidVault 适配器，默认读取：

```text
%LOCALAPPDATA%\BidVault\data\vault.sqlite3
%LOCALAPPDATA%\BidVault\data\files\
```

适配器以只读方式打开 SQLite，并读取 `records`、`attachments`。只接受 `performance` 和 `certificate` 类型，附件路径必须仍位于 BidVault 的 `files` 目录内。

字段映射如下：

- `performance` 保持为项目业绩，映射项目名称、客户、分类、金额、日期、标签、备注和附件。
- `certificate` 保持为人员证书，映射人员姓名、证照名称、专业、等级、证书号、签发日、到期日、长期有效、标签、备注和附件。
- 易标材料 ID 使用 `bidvault:<源记录 ID>`，保证重复同步幂等。
- `companyId` 写入“隆创信息有限公司”；本次用户确认作为源库整体主体归属确认。
- 附件沿用 BidVault 已保存的 SHA256，但同步阶段仍检查文件存在、路径边界和 SHA256 格式。

同步会替换上一次来自 BidVault 的同 ID 快照，并保留仍存在材料的已选状态和资格要求关联；手工 JSON 导入的材料不受影响。源库删除的记录从候选列表移除。同步失败时保留上一次成功结果。

## 附件存储与校验

同步阶段不复制 9.47 GB 附件，也不在 Electron 主线程全量重算哈希。材料第一次被人工选用时，易标在 `workspace/business-bid/evidence/` 中为附件创建硬链接；目标已存在时复用。硬链接失败时保留源文件引用并给出可操作提示，不静默复制整个资料库。

生成和导出前继续执行现有 SHA256 校验，只校验已选材料。这样既避免重复磁盘占用和长时间阻塞，也保证最终采用的证据原件未发生变化。BidVault 删除源附件不会影响已经成功建立的硬链接。

## 可用性规则

- 有完整附件的业绩可以进入可选候选；缺少附件或附件路径失效时标为“待补资料”。
- 证书必须具有有效到期日或长期有效标记；缺少有效期、已过期或附件缺失时标为“待核实”。
- BidVault 没有人员任职证明模型，因此人员证书同步后默认缺少任职归属证据，不能直接出标。用户仍可通过现有公司证据台账入口补充劳动合同、社保证明或任职文件。
- 任何待核实材料都不能因前端勾选而绕过生成与导出校验。

## 代码边界

- `client/electron/services/bidVaultEvidenceSource.cjs`：只读打开旧库、校验路径并转换字段。
- `client/electron/services/businessBidStore.cjs`：合并同步结果、保留选择、按需建立附件硬链接。
- `client/electron/ipc/businessBidIpc.cjs`、`client/electron/preload.cjs`、`client/src/shared/types/ipc.ts`：增加同步 IPC。
- `client/src/features/business-bid/pages/BusinessBidPage.tsx`：增加同步入口、统计和列表上限提示。
- `client/src/features/business-bid/types.ts`：补充同步来源与统计类型。
- `client/electron/services/*.test.cjs` 与 `client/scripts/business-bid-smoke.cjs`：覆盖转换、幂等、主体隔离、附件复用和 UI 入口。

首期不修改通用文档知识库表。BidVault 数据属于结构化公司证据，直接进入商务标证据库可以保留有效期、主体、附件哈希和资格关联；把 1,638 条结构化记录拼成文档再交给知识库模型解析会丢失这些约束并产生不必要的模型费用。

## 错误处理

- 找不到 BidVault、数据库打不开或表结构不兼容时，显示具体路径和处理建议。
- 同步使用事务式内存结果：全部读取、转换成功后才覆盖易标中的上次同步快照。
- 单条附件缺失只影响对应材料，其余记录继续同步并计入“待补资料”。
- 同步时商务标正在提取或生成，则沿用现有 `assertIdle` 拒绝修改。
- 选择材料时硬链接失败会保留源引用并提示；生成前源文件不存在或哈希不符时阻止生成。

## 验证标准

- 合成 BidVault SQLite 可同步业绩和人员证书，字段、排序、状态和附件路径正确。
- 同一源库重复同步不产生重复项，并保留仍存在材料的选择与资格关联。
- 切换到云界公司时不能同步隆创源库。
- 手工导入材料不会被同步删除。
- 选择材料会优先建立硬链接；生成前能发现源文件缺失或篡改。
- 缺附件、证书缺有效期和人员缺任职证明均保持待核实。
- 真实本机库同步后数量为 1,638 条，并能从页面检索和选用业绩。
- Electron 服务定向测试、原生烟测、商务标隔离烟测和 `npm run build` 通过。
