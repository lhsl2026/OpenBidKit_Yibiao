# 商务标第一版设计

来源：本任务明确实施指令；基线 `3eddc2b`，`codex/feishu-integration`，开始时工作区干净。

## 目标与边界

为隆创信息有限公司生成可复核的商务标 DOCX 草稿及待补资料清单。上传招标文件，提取商务目录、资格要求、废标项、表单字段和商务条款；导入既有公司证据库的 records 快照，匹配候选并由员工确认，再生成材料。报价只生成空白结构；不计算价格、不签章、不提交投标。

## 方案选择

采用独立商务标工作区，复用文件解析、任务管理、任务级模型配置及 Word 导出。直接复用技术标工作区会覆盖已有技术方案；另建后台任务框架则重复取消和恢复机制，因此均不采用。正文采用确定性商务模板和已确认事实，模型负责招标要求提取，不让模型补写公司事实。

## 数据与流程

- `business_bid_workspace` 保存单工作区结构化 JSON（源文件、分析、证据、确认、字段值、正文、后台任务），由 SQLite migration v25 管理。原文与公司附件副本位于工作区文件目录。
- Main 受管提取任务按模型上下文分段，逐段 checkpoint；每条提取项保存文件、段号、原文摘录。摘录无法在对应输入中找到时拒绝该段结果，不默认为完整分析。失败不自动重启；重新提取从头开始并清除下游。
- 五类提取数组：directory、qualifications、disqualifications、fields、terms。不截断长文件；空结果保留待核实提示。员工确认分析后才能生成。
- 公司快照沿用飞书证据库 records/attachments 格式；只接纳明确公司归属、verified、附件 verified 且本地 SHA256 与台账一致的材料。异名排除，其他材料显示待核实且不能勾选。人员额外要求 employmentEvidence 的归属与附件证据。证书有效期缺失/过期保留待核实，核对时点取当前日与人工填写的投标截止日较晚者。
- 候选按要求关键词排序展示，员工勾选材料及其对应要求。确认只表示选作草稿材料，不表示已经满足资格条件。更新文件、证据或分析使正文失效，重新确认；普通页面卸载不取消后台任务。
- 生成投标函、法定代表人身份证明、授权书、资格资料、资质/人员/业绩、商务偏离表、政策声明、报价表结构；保留招标目录与所有表单字段。缺失值显示“待核实”。投标函、授权和声明均为待人工审核草稿，政策身份、无偏离和履约承诺不自动判断。
- 已确认附件生成材料索引及核验信息；第一版不承诺复制招标原件的精确版式或自动合并 PDF 扫描附件。待补清单明确列出需人工装订的原件/扫描件和招标格式核对工作。
- 整本和待补清单分别复用 exportService 输出 DOCX，保存成功后可打开，显示现有导出进度。正文与清单保持同一生成快照。

## 页面

替换 BusinessBidPage 演示内容：上传与模型选择、要求清单及来源、字段人工填写、证据候选确认、草稿预览与导出。沿用中文文案、Toast、MarkdownRenderer（禁用原始 HTML）、全局 CSS 与页面内部滚动。开始新项目需明确确认。

## 验收

聚焦测试验证：异名/未核实/附件缺失/哈希不符/人员归属不足不能使用；未经人工确认不能生成；报价字段始终为空；来源引用核对；长文件分段与失败状态；下游失效及重启恢复；DOCX 含全部章节和待补资料。运行改动 CJS 语法检查、TypeScript/Vite build、Electron native smoke、隔离 SQLite/IPC/页面验收，不调用真实公司模型、不触碰生产群。
