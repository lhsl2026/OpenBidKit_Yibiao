# 公告附件部分预读与完整文件自动升级设计

## 目标

当贵州公共资源交易公告尚未公开完整 `.ZYZF` 招标包、但只公开一份可信 PDF 采购需求附件时，系统自动下载并解析该附件，向飞书发布明确标注“非完整招标文件”的部分预读报告，同时保留完整文件缺失状态和人工补传入口。系统继续轮询同一官方公告，完整包出现后自动接入新版本并升级为完整预读。

## 数据流

1. OpenBidKit 恢复器读取官方公告页及详情接口。
2. 优先选择唯一合法 `.ZYZF` 包；没有完整包时，只接受唯一、HTTPS、可信主机、20 MiB 以内且通过 PDF 头尾校验的公告 PDF。
3. 完整包返回 `obtained`；公告 PDF 返回 `partial_obtained`，二者都携带 SHA-256、中文用途文件名和来源证明。
4. OpenBidKit 以 `announcement_attachment` 上传部分附件。预读底座保存并解析它，将任务置为 `partial`，生成部分报告，但不关闭“补齐完整招标文件”的人工动作，也不启动写标交接。
5. OpenBidKit 将作业置为 `monitoring`。同一附件按 SHA-256 幂等跳过；网络结果不明时只延后轮询，不重复上传、不触发模型。
6. 发现 `.ZYZF` 后按 `tender_document` 接入。预读底座创建新文档版本，重新解析并生成完整报告；OpenBidKit 仅在此时绑定可用于写标的完整原文。

## 安全与判断边界

- 公告附件不能标记为完整招标文件，也不能解锁标书初稿。
- 部分报告必须显示文件级别和缺项；资格结论、评分地图、废标风险及最终投标建议保持待核实。
- 只接受贵州官方详情接口中的唯一 PDF；多 PDF、非 PDF、未知主机、重定向、超限、签名不符均转人工处理。
- 远程上传或接入结果不明时进入人工状态，绝不自动重放有副作用的远程写操作。
- 公司证据仍只使用“隆创信息有限公司”的既有台账。

## 状态与幂等

- `download -> downloaded -> uploaded -> monitoring` 表示部分附件已接入并持续监控。
- `monitoring -> downloaded -> uploaded -> attached` 表示发现并接入完整文件。
- 作业记录保存附件类别和 SHA-256；相同部分附件只更新下次检查时间。
- 预读人工动作在部分附件接入后释放 claim 并保持 open，完整文件接入后才 resolve。

## 验收

- 单元测试覆盖唯一可信 PDF、主机/协议/重定向/数量/大小/PDF 签名边界。
- OpenBidKit 测试证明上传类别为 `announcement_attachment`、部分附件不绑定写标原文、监控幂等、完整包升级。
- 预读测试证明部分附件会解析并生成部分报告、人工动作保持 open、五模块写标交接不启动、完整文件可从 `partial` 升级。
- 真实项目生成飞书部分报告和归档文档，卡片明确显示“采购需求稿／非完整招标文件”，并保留持续监控。
